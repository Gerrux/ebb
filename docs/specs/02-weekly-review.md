# 02 — Weekly Review

Статус: core реализован в отдельном окне Ebb; детали ниже остаются целевым UX для следующих итераций.

## Зачем

product.txt §13, §11, §12. Автоматика (01) только помечает кандидатов в архив — решение
принимает человек, но за минуты, а не за вечер. У пользователя после импорта ~430 заметок;
разбирать их списком никто не будет.

## Поведение

1. Раз в неделю (день и время в настройках, по умолчанию пятница 16:00) на слое спокойно
   появляется карточка-приглашение «Разобрать 12 заметок · ~3 мин». Без уведомлений Windows.
   Пропустить можно; через 3 дня приглашение исчезает само.
2. Review открывается в отдельном окне (создаётся по требованию, как библиотека) — стопка
   карточек по одной, крупно.
3. Для карточки (§13): **Оставить** (←), **В архив** (→), **Позже** (↓, snooze на 2 недели),
   **Закрепить** (↑), **В корзину** (Delete), **Сделать целью** (G). Мышь: кнопки под карточкой;
   свайп-жесты мышью/тачпадом — перетаскивание влево/вправо.
4. Прогресс «4 из 12», «Отменить последнее» (Ctrl+Z) на всю сессию.
5. Размер сессии ограничен: максимум 15 карточек (настраивается). Если кандидатов больше —
   берутся самые «забытые», остальные ждут следующей недели.
6. Итог: «Оставлено 5, в архив 6, позже 1» и закрыть. Никаких графиков продуктивности (§27).

Кандидаты, по приоритету:
1) кандидаты в архив из decay (01 §6);
2) карточки на слое, не открывавшиеся ≥ 30 дней;
3) напоминания с прошедшим сроком без действия;
4) (первые недели после импорта) импортированные заметки из архива, не открывавшиеся в Ebb.

## UI

Окно 520×640, по центру монитора под курсором, акрил, скругления. Карточка — как на слое, но
крупнее (шрифт 17), с причиной сверху («Не открывал 47 дней»). Анимация ухода карточки в сторону
действия (120 мс).

## Данные

```sql
CREATE TABLE reviews(id INTEGER PRIMARY KEY, started_at INTEGER, finished_at INTEGER,
                     kept INTEGER, archived INTEGER, snoozed INTEGER, trashed INTEGER, pinned INTEGER);
CREATE TABLE review_items(review_id INTEGER, card_id INTEGER, action TEXT, at INTEGER);
```
Нужны для «Отменить последнее» и чтобы решение «Оставить» сбрасывало `ignored_count` и
откладывало карточку от следующего review на 8 недель.

## Реализация

`review.rs` — выбор кандидатов (чистая функция, тесты) и окно (deferred viewport по образцу
`library.rs`). Планирование приглашения — тот же планировщик, что в 01.

## Критерии приёмки

- [ ] Вся сессия проходится только клавиатурой.
- [ ] «Отменить последнее» возвращает карточку в исходное состояние (архив/pin/snooze/корзина).
- [ ] Карточка с решением «Оставить» не появляется в review 8 недель.
- [ ] Окно после закрытия уничтожено, working set возвращается (как у библиотеки).
- [ ] Приглашение не показывается, если кандидатов < 3.

## Не делаем

Статистику по неделям, серии, напоминания-уведомления, обязательность.
