# Ebb — спецификации дальнейшего развития

Источник продукта: [`product.txt`](../../product.txt). Здесь — как довести его до MVP и дальше
на текущей архитектуре (Rust, egui/eframe 0.36 + glow, SQLite/FTS5, Win32).

## Главный вопрос для каждой фичи

> Помогает ли это пользователю помнить нужное — или создаёт систему, которую придётся обслуживать?
> (product.txt §29)

Если фича требует от пользователя регулярной «уборки», она должна делать эту уборку сама
или не делаться.

## Инженерные ограничения (не ухудшать без обсуждения)

Цифры — release, медианы, замерены `scripts/bench.ps1` (≥ 5 прогонов, вперемешку с базовой сборкой).
Запуск из шелла приложения Claude добавляет ~40 мс (MSIX-виртуализация) — сравнивать только A/B.

| Метрика | Сейчас | Бюджет |
|---|---|---|
| Первый кадр от старта процесса | ~290 мс (254 мс вне контейнера) | ≤ 350 мс |
| Простой: working set / private | 2,5 / ~105 МБ | WS ≤ 5 МБ, private ≤ 115 МБ |
| CPU в простое | 0 мс / 3 с | 0 (≤ 1 тик планировщика) |
| Хоткей → кадр окна захвата | ~15 мс | ≤ 30 мс |
| Хоткей → кадр окна поиска | ~21 мс | ≤ 40 мс |
| Поиск, 10 000 заметок, попадание | p95 ≤ 7 мс | p95 ≤ 20 мс |
| Поиск, полный промах | ~25 мс | ≤ 50 мс |
| Импорт 468 Sticky Notes (скан) | 140–190 мс в фоне | фон, не на UI-потоке |

Правила, выведенные из замеров:

- **Никакого поллинга.** Таймеры — только `request_repaint_after` до ближайшего события; фоновые
  события — через блокирующие ожидания (`GetMessageW`, waitable timer).
- **Ничего тяжёлого до первого кадра.** Фоновые задачи стартуют не раньше чем через 2–3 с и с
  `THREAD_MODE_BACKGROUND_BEGIN`.
- **Не вызывать `DwmFlush`** рядом с показом окон (задерживал первый показ на ~170 мс).
- **Окна создаются по необходимости**, кроме бара (он заранее создан ради задержки захвата).
  Окно, созданное при открытии, после закрытия уничтожается.
- **UI-поток не ждёт сети, COM, диска > 5 мс.**
- **Данные пользователя не покидают машину** без явного действия (§22).

## Как проверять

- Юнит-тесты: логика (парсинг, планирование, SQL) — `cargo test --release`.
- UI: egui_mcp на порту 5731 (`EGUI_INSPECTION=127.0.0.1:5731`, сборка `--features inspection`);
  второй экземпляр рядом с рабочим — `EBB_INSTANCE=test`, отдельные данные — `LOCALAPPDATA=<dir>`.
- Окна вне egui (бар, библиотека, трей): `scripts/verify-shell.ps1`, скриншоты, синтетический ввод
  только в окно Ebb на переднем плане.
- Производительность: `scripts/bench.ps1`, A/B против предыдущего коммита.
- Реальные заметки пользователя в скриншоты и логи не попадают: тестовый профиль с синтетикой.

## Текущая модель данных (для справки)

```sql
cards(id, kind, title, body, tags /*csv*/, pinned, archived,
      x, y, w, h, created_at, updated_at, last_viewed_at, deleted_at)
cards_fts  -- FTS5 external content (title, body, tags), unicode61 remove_diacritics 2
settings(key, value)          -- layer.monitor, layer.backdrop, layer.tint, layer.pin_bottom, layer.collapsed, sticky_import
imported(source_id, card_id, batch)
```

Модули: `app` (слой), `bar` (захват/поиск), `library` (архив/корзина/настройки), `shell` (трей,
хоткеи, единственный экземпляр), `store` (SQLite), `search` (разбор запроса), `sticky` (импорт),
`import_ui`, `autostart`, `win` (Win32), `card`, `theme`, `bench`, `renderer`.
